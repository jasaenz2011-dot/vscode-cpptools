## KQ2. What does the Blender glTF exporter (Blender 4.x/5.x, Oct 2026) write from Principled BSDF, how must nodes be wired, and what are the limits?

### Takeaway
The built-in exporter writes KHR_materials_transmission, _volume, _ior, _specular, _clearcoat, _sheen, _emissive_strength, _dispersion, _texture_transform and _variants (variants via a dedicated UI, not a node), plus Draco/meshopt compression, WebP textures and gltfpack integration; thickness/occlusion/dispersion require the "glTF Material Output" node group, and the alpha mode is deduced from the Alpha socket wiring (Opaque / Mask via rounding Math node / otherwise Blend).

### Cited Findings
- **Add-on version/branches**: `bl_info` version (5, 4, 4), minimum Blender (5, 3, 0), support OFFICIAL. **Documented** — [io_scene_gltf2/__init__.py](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/addons/io_scene_gltf2/__init__.py). Branches: 4.5 LTS (`blender-v4.5-release`), 5.0 (`blender-v5.0-release`, "current stable release"), 5.1 (`blender-v5.1-release`, "next stable"), `main` → Blender 5.2; bundled with Blender 2.80+. **Documented** — [glTF-Blender-IO README](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/README.md).
- **Base color / metallic-roughness**: Base Color read from Principled BSDF (Image Texture → base color texture; unconnected → socket color). "glTF expects the metallic values to be encoded in the blue (B) channel, and roughness to be encoded in the green (G) channel"; use a Separate RGB (Separate Color) node; set non-color textures to Non-Color. **Documented** — [scene_gltf2.rst (glTF-Blender-IO copy of the Blender manual page)](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst) (public: https://docs.blender.org/manual/en/latest/addons/import_export/scene_gltf2.html).
- **Emission / emissive strength**: Image Texture to Emission input, or an Emission shader via Add Shader. "If any component of emissiveFactor is > 1.0, KHR_materials_emissive_strength extension will be used." **Documented** — same page.
- **Transmission**: `KHR_materials_transmission` written when Transmission is non-zero or textured (R channel, Non-Color); transmission "allows full-strength specular reflections". **Documented** — same page.
- **IOR**: written only if transmission, volume or specular is used; "a value of 1.5 is never written" (1.5 is the glTF default). **Documented** — same page.
- **Volume / thickness**: a Volume Absorption node connected to the Material Output's Volume socket and transmission set; absorption color → attenuationColor (no texture allowed); density → inverse of attenuationDistance; thickness plugs into the **glTF Material Output** node group (thickness texture read from G). **Documented** — same page.
- **Dispersion**: `KHR_materials_dispersion` requires `KHR_materials_volume`; uses the Dispersion socket of glTF Material Output. **Documented** — same page.
- **Specular / clearcoat / sheen / anisotropy**: Specular written when Specular IOR Level or Specular Tint non-default or textured; Clearcoat when non-zero/textured (texture R = clearcoat, G = roughness; clearcoat normal may reuse base normal); Sheen roughness texture read from A, "The Sheen BSDF is only available in Cycles"; anisotropy via specific conversion nodes, tangent must link to a Tangent node with the same UV map as the normal map. **Documented** — same page.
- **Iridescence**: described but absent from the import/export supported-extension lists on the page (doc inconsistency). **Documented (inconsistent source)** — same page.
- **Alpha modes**: exporter picks from the Alpha socket: Opaque (alpha always 1), Mask (use a Math node to round alpha to 0/1, or `1 - (alpha < cutoff)` for a custom cutoff), Blend otherwise, with the warning that viewers may show artifacts. The page I read does not describe Blender's Hashed/Dithered viewport modes as affecting export. **Documented** — same page.
- **Double-sided**: inverse of EEVEE Backface Culling sets glTF `doubleSided`. **Documented** — same page.
- **KHR_texture_transform**: UV Map + Mapping (Point) node → Image Texture; Location X/Y, Rotation Z, Scale X/Y supported; Texture type requires uniform scale. **Documented** — same page.
- **Export options**: GLB / glTF Separate / glTF Embedded ("least efficient"); Images: PNG / JPEG / WebP / None — "If WebP is chosen, all textures will be saved as WebP, without any png/jpg fallback"; Create WebP + WebP fallback options; Draco (compression level + per-attribute quantization; "Higher compression results in slower encoding and decoding"); Meshopt: `EXT_meshopt_compression` or `KHR_meshopt_compression`; Shape keys (normals/tangents, sparse accessors, shape-key animations); Animation modes Actions / Active Actions merged / NLA Tracks / Scene; "Optimize Animation Size"; sampling rate; Punctual lights (`KHR_lights_punctual`). **Documented** — same page; property names (`export_draco_mesh_compression_enable`, `export_meshopt_compression_enable`, `export_meshopt_extension`, `export_image_format`, `export_image_add_webp`, `export_image_webp_fallback`, `export_use_gltfpack`, `export_gltfpack_tc`, `export_gltfpack_tq`, `export_try_sparse_sk`) confirmed in [__init__.py](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/addons/io_scene_gltf2/__init__.py).
- **KHR_materials_variants export exists** (contrary to "no variants export natively"): managed from the 3D View "glTF Variants" tab after enabling the UI in add-on preferences (`KHR_materials_variants_ui`); create variants, "Assign to Variant", "Assign as Original", "Display Variant", "Reset to default"; "Each material slot acts as a glTF primitive." **Documented** — [scene_gltf2.rst](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst); `KHR_materials_variants_ui` preference in [__init__.py](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/addons/io_scene_gltf2/__init__.py).
- **Limitations stated**: only Principled BSDF and Shadeless (Unlit) materials export; quads/n-gons triangulated; non-PNG/JPEG images converted ("increasing export time"); UDIMs split per tile; only transforms, pose bones and shape-key values animate ("Animation of other properties, like physics, lights, or materials, will be ignored"); area lights and World lighting not exported; Animation Pointer experimental; "transmissive materials may not be visible behind other transmissive materials" and transmission support is limited in many engines. **Documented** — same page.
- **Babylon's own Blender→glTF page**: glTF add-on "enabled in Blender by default" since 2.8; export .gltf/.glb; the loader puts assets under `__root__` rotated 180° on Y and scaled −1 on Z — do not pre-correct axes; validate in the Sandbox or Viewer. **Documented** — [Blender_to_glTF.md](https://raw.githubusercontent.com/BabylonJS/Documentation/master/content/features/featuresDeepDive/Exporters/Blender_to_glTF.md) (public: https://doc.babylonjs.com/features/featuresDeepDive/Exporters/Blender_to_glTF).
- Blender 5.3 release notes (search excerpt only): glTF exporter gained Animation Pointer export of extras custom properties and a material node-tree performance improvement. **Documented (excerpt)** — [Blender 5.3 Pipeline & I/O notes](https://developer.blender.org/docs/release_notes/5.3/pipeline_io/). A third-party guide claims meshopt export arrived in 5.2 — **Unverified** — [cinevva guide](https://app.cinevva.com/guides/blender-5-for-game-artists); the `export_meshopt_*` properties exist in `main` (**Documented**), but the exact version that introduced them was not confirmed.

### Inferences
- For the frosted shell: Principled BSDF with Transmission > 0, Roughness ≈ 0.3–0.6, IOR ≈ 1.45–1.5 (note: 1.5 will not be written; the loader defaults to 1.5 anyway), plus a Volume Absorption node and a thickness value/texture through glTF Material Output, exports transmission + volume + ior and optionally dispersion. **Inferred from the mapping above**.
- A "Dithered" or "Blended" EEVEE render method does not by itself set the glTF alpha mode; the Alpha socket wiring does. **Inferred** (the page describes only socket-based detection).

- Official Blender 5.0/5.1/5.2 release notes (developer.blender.org) were unreachable; which exact version added meshopt and gltfpack integration remains unconfirmed.
- The official docs.blender.org page for Blender 5.x could not be opened; the in-repo copy may differ slightly from the version-specific manual.

## KQ3. How does Babylon.js render glTF transmission, what does it cost, and what are the practical ways to get a frosted translucent shell with visible metallic internals?

### Takeaway
On import, a transmissive glTF material turns on `PBRMaterial.subSurface` refraction and the loader creates a scene-wide `TransmissionHelper` that renders all opaque meshes into a second 1024² half-float, 4×-MSAA, mipmapped render target used as the refraction texture — i.e. the opaque scene is drawn twice. For a mobile avatar, the documented levers are: keep the shell as the only transmissive material, lower the helper's `renderSize`, or avoid transmission entirely with alpha-blended/alpha-test shells plus `needDepthPrePass` / `separateCullingPass` / rendering-group ordering, or bake internals into textures.

### Cited Findings
**What the loader does**
- `KHR_materials_transmission`: when used, sets `loader.parent.transparencyAsCoverage = true`; for weight > 0 calls `adapter.configureTransmission()`, sets `adapter.transmissionWeight`, loads the transmission texture as non-color, and calls `ensureTransmissionHelper(...)`; extension `order = 175`. **Documented** — [KHR_materials_transmission.pure.ts](https://raw.githubusercontent.com/BabylonJS/Babylon.js/master/packages/dev/loaders/src/glTF/2.0/Extensions/KHR_materials_transmission.pure.ts).
- Adapter → `PBRMaterial` mapping: `configureTransmission()` sets `subSurface.volumeIndexOfRefraction = 1.0`, `subSurface.useAlbedoToTintRefraction = true`, min/max thickness 0; `transmissionWeight` → `subSurface.isRefractionEnabled = value > 0` and `subSurface.refractionIntensity = value`; `refractionBackgroundTexture` → `subSurface.refractionTexture`; `emissionLuminance` → `emissiveIntensity`; `subsurfaceWeight` (diffuse transmission) → `subSurface.isTranslucencyEnabled = value > 0` and `translucencyIntensity`; `diffuseTransmissionTint` → `subSurface.tintColor`; `diffuseTransmissionTintTexture` → `translucencyColorTexture`; `volumeThickness` → `subSurface.maximumThickness` (+ `useThicknessAsDepth = true`, and `volumeIndexOfRefraction` = material IOR when > 0); `transmissionColor`/`transmissionDepth` → `tintColor`/`tintColorAtDistance` when transmission > 0. **Documented** — [pbrMaterialLoadingAdapter.ts](https://raw.githubusercontent.com/BabylonJS/Babylon.js/master/packages/dev/loaders/src/glTF/2.0/pbrMaterialLoadingAdapter.ts).
- `KHR_materials_volume`: does nothing unless `transmissionWeight` or `subsurfaceWeight` is non-zero and `thicknessFactor` is truthy ("it requires either the KHR_materials_transmission or KHR_materials_diffuse_transmission extensions"); thickness texture loaded as non-color; attenuationColor → `transmissionColor` (default white), attenuationDistance → `transmissionDepth` (default `Number.MAX_VALUE`); **disables instanced meshes** for the file ("the attenuation factor depends on the node scale of each individual mesh"); `order = 173`. **Documented** — [KHR_materials_volume.pure.ts](https://raw.githubusercontent.com/BabylonJS/Babylon.js/master/packages/dev/loaders/src/glTF/2.0/Extensions/KHR_materials_volume.pure.ts).
- `KHR_materials_diffuse_transmission`: `subsurfaceWeight` = diffuseTransmissionFactor (default 0), `diffuseTransmissionTint` = colorFactor (default white), textures as non-color; also sets `transparencyAsCoverage = true` and, for weight > 0, **also creates the TransmissionHelper** (changelog 9.9.0 "Trigger transmission helper from KHR_materials_diffuse_transmission"). Marked experimental in source. **Documented** — [KHR_materials_diffuse_transmission.pure.ts](https://raw.githubusercontent.com/BabylonJS/Babylon.js/master/packages/dev/loaders/src/glTF/2.0/Extensions/KHR_materials_diffuse_transmission.pure.ts); [CHANGELOG.md](https://raw.githubusercontent.com/BabylonJS/Babylon.js/master/CHANGELOG.md).

**TransmissionHelper internals (the cost)**
- Defaults: `renderSize: 1024`, `samples: 4`, `lodGenerationScale: 1`, `lodGenerationOffset: -4`, `renderTargetTextureType: TEXTURETYPE_HALF_FLOAT`, `generateMipmaps: true`; clear color = scene clear color in linear space with alpha forced to 0. It creates a `RenderTargetTexture` named `"opaqueSceneTexture"` with `renderList` = every opaque (and the opaque submeshes of "mixed" multi-material) mesh in the scene, `forceLayerMaskCheck = true`, `renderSprites`/`renderParticles` true, `disableImageProcessing = true`, and temporarily sets `environmentIntensity = 1.0` while rendering it. Fully transmissive meshes are excluded from the opaque target and receive `refractionBackgroundTexture = opaqueRenderTarget`. Meshes are re-classified via `onNewMeshAddedObservable`, `onMeshRemovedObservable` and per-mesh `onMaterialChangedObservable`. The helper is attached as `scene._transmissionHelper`; `ensureTransmissionHelper` is skipped if `loader.parent.dontUseTransmissionHelper` is set. No explicit performance comment exists in the source. **Documented** — [transmissionHelper.ts](https://raw.githubusercontent.com/BabylonJS/Babylon.js/master/packages/dev/loaders/src/glTF/2.0/Extensions/transmissionHelper.ts).
- Forum (search excerpts, not full threads): a user reported "pretty strong perf degradation" for larger scenes with the transmission helper and asked whether "the entire scene is rendered twice"; maintainers said the helper class was internal and might change; rough refraction blur relies on the refraction texture's mip levels (`lodGenerationOffset`), which "will become blocky when using some higher values". **Documented (excerpt), 5.x-era** — [Transmission helper optimisation](https://forum.babylonjs.com/t/transmission-helper-optimisation/21037); [Refraction of other objects](https://forum.babylonjs.com/t/refraction-of-other-objects/42896/8); [PBR Refraction roughness (blurriness)](https://forum.babylonjs.com/t/pbr-refraction-roughness-blurriness/23334); [Enable KHR settings (transmission) in runtime](https://forum.babylonjs.com/t/enable-khr-settings-transmission-in-runtime/43686).
- Khronos spec implementation notes: "thin" model only (surface considered, volume not; absorption constant = 1 − baseColor); implementations "should show at least opaque objects through a transmissive material", transmitting only IBL "often falls short of the author's intent"; if infeasible, "simple alpha blending with 0 < alpha < 1" is the suggested fallback; `alphaMode` is for coverage, not physical transparency, and a transmissive material not using coverage should be OPAQUE. **Documented** — [KHR_materials_transmission spec](https://github.com/KhronosGroup/glTF/blob/main/extensions/2.0/Khronos/KHR_materials_transmission/README.md). KHR_materials_diffuse_transmission is listed as **Release Candidate**, models "light being diffusely transmitted through an infinitely thin material", with a simple Lambert BTDF as the only implementation note. **Documented** — [KHR_materials_diffuse_transmission spec](https://github.com/KhronosGroup/glTF/blob/main/extensions/2.0/Khronos/KHR_materials_diffuse_transmission/README.md).

**PBRMaterial sub-surface controls (manual alternatives)**
- `subSurface.isRefractionEnabled`, `refractionIntensity`, `indexOfRefraction` (nomenclature value, e.g. 1.5); `tintColor`, `tintColorAtDistance` (Beer-Lambert); thickness = `maximumThickness` by default, or `minimumThickness + thicknessTexture.r * maximumThickness`; `useMaskFromThicknessTexture` packs G = translucency intensity, A = refraction intensity. `isTranslucencyEnabled`/`translucencyIntensity` "simulate light diffusing through denser materials like milk" with the same tint/thickness controls. `isScatteringEnabled` (true SSS) "Requires WebGL 2, triggers a post-process, and adds significant GPU work… use it wisely". Legacy path: `refractionTexture` + `linkRefractionWithTransparency`. `useRadianceOverAlpha`/`useSpecularOverAlpha` keep reflections visible over alpha. Clear coat (`clearCoat.isEnabled/intensity/roughness/tint*`), sheen, iridescence and anisotropy sub-objects exist. **Documented** — [masterPBR.md](https://raw.githubusercontent.com/BabylonJS/Documentation/master/content/features/featuresDeepDive/materials/using/masterPBR.md) (public: https://doc.babylonjs.com/features/featuresDeepDive/materials/using/masterPBR).

**Transparency, sorting, depth**
- Draw order: depth pre-pass → opaque → alpha-tested → sprites → particles → alpha-blended; alpha-blended meshes sorted back-to-front by distance from camera to **bounding-sphere center**; `alphaIndex` (default `Number.MAX_VALUE`) sorts first, then depth; `renderingGroupId` (4 groups by default, raise with `RenderingManager.MAX_RENDERINGGROUPS`). Blended meshes do not write depth. "Backface culling is practically required for alpha-blended meshes." `needDepthPrePass = true` adds a depth-only pass that "reduces overdraw or alpha-sorting problems… helps with self-transparency". `separateCullingPass` renders back faces then front faces (disables `twoSidedLighting`). `transparencyMode`: `MATERIAL_OPAQUE`, `MATERIAL_ALPHATEST` (default cutoff 0.4 via `alphaCutOff`), `MATERIAL_ALPHABLEND`, `MATERIAL_ALPHATESTANDBLEND`; PBR still uses albedo alpha even when `useAlphaFromAlbedoTexture = false`. OIT: `scene.useOrderIndependentTransparency = true` (dual depth peeling, `passCount` default 5 → up to 10 layers), WebGL2/WebGPU only, beta, renders transparent meshes "many more times", **refraction textures unsupported**, no anti-aliasing. Performance tips: prefer alpha test; `ALPHA_PREMULTIPLIED` blend modes avoid needing pre-pass/culling pass; avoid intersecting blended meshes. **Documented** — [transparent_rendering.md](https://raw.githubusercontent.com/BabylonJS/Documentation/master/content/features/featuresDeepDive/materials/advanced/transparent_rendering.md) (public: https://doc.babylonjs.com/features/featuresDeepDive/materials/advanced/transparent_rendering).
- Environment: `scene.environmentTexture` from a prefiltered `.env` (`CubeTexture.CreateFromPrefilteredData` or `new CubeTexture("x.env")`); `.env` generated in the Sandbox (Inspector → Tools → "Generate .env texture"; a diffuse option adds ~10 KB since 7.48.0) or the IBL Texture Tool; a 512 px `.env` is ~3 MB vs ~32 MB unpacked; on-the-fly prefiltering of .hdr/.exr needs WebGL2 and delays loading, so `.env`/`.dds` preferred. **Documented** — [HDREnvironment.md](https://raw.githubusercontent.com/BabylonJS/Documentation/master/content/features/featuresDeepDive/materials/using/HDREnvironment.md).

### Inferences
- **Cost model for the shell**: with glTF transmission, every opaque mesh (body, limbs, T-shirt, internals, environment props) is drawn twice per frame (main pass + 1024² MSAA-4 half-float opaque target with mip generation). On a phone this is roughly a second full geometry pass at ~1 MP plus MSAA resolve and mip chain; the helper's `renderSize`/`samples` can be reduced via `scene._transmissionHelper.updateOptions({...})` but that API is internal/underscored. **Inferred** from transmissionHelper.ts and forum excerpts.
- **Frosted plastic without transmission (mobile-first option)**: a `MATERIAL_ALPHABLEND` shell with `alpha ≈ 0.3–0.6`, roughness ≈ 0.5, `backFaceCulling = true`, `needDepthPrePass = true` (so the shell's own back faces don't pop), internals drawn opaque underneath; sorting is by bounding-sphere center, so keep shell and internals as separate meshes with the shell's `alphaIndex` higher than any blended internals and rely on the opaque pass for metallic parts. **Inferred** from the transparent-rendering doc.
- **Diffuse transmission ("milky") as a middle option**: `isTranslucencyEnabled` is cheaper conceptually than scattering (no post-process), but in 9.x the glTF loader *also* spins up the TransmissionHelper for diffuse_transmission, so the import path does not avoid the extra pass; setting `subSurface.isTranslucencyEnabled` manually on a non-transmissive material (or disabling the extension via `extensionOptions`/`dontUseTransmissionHelper`) would avoid the helper. **Inferred** from the 9.9.0 changelog line and the adapter mapping; needs testing.
- **Baked internal detail** (metallic internals painted into albedo/emissive of a blended shell, or an opaque inner mesh with parallax-like depth painted in) is the only approach with zero extra passes and is the alpha-blend fallback the Khronos spec itself endorses for weak renderers. **Inferred**.
- OIT is not a fit here because refraction textures are unsupported under OIT and it multiplies transparent passes. **Inferred** from the doc's limitations list.

### Gaps
- No official Babylon document quantifying the transmission helper's mobile cost; the forum perf report is from the 5.x era and unanswered in the excerpt.
- Node Material Editor tricks for frosted glass were not researched (no reachable source in this session).
- I could not verify the current status of the public "transmission" docs page or whether `dontUseTransmissionHelper` is documented publicly (it is in source).

## KQ4. Emissive sole with glow: emissive_strength support and GlowLayer/HighlightLayer cost

### Takeaway
`KHR_materials_emissive_strength` is read and mapped to `PBRMaterial.emissiveIntensity`; a `GlowLayer` makes all emissive output glow by rendering emissive parts to a scaled render target and blurring (kernel 32 by default), with `mainTextureRatio` ("the smaller, the faster") and `mainTextureFixedSize` as the primary mobile knobs.

### Cited Findings
- Loader: `adapter.emissionLuminance = properties.emissiveStrength` when present (`order = 170`); adapter maps `emissionLuminance` → `emissiveIntensity`. **Documented** — [KHR_materials_emissive_strength.pure.ts](https://raw.githubusercontent.com/BabylonJS/Babylon.js/master/packages/dev/loaders/src/glTF/2.0/Extensions/KHR_materials_emissive_strength.pure.ts); [pbrMaterialLoadingAdapter.ts](https://raw.githubusercontent.com/BabylonJS/Babylon.js/master/packages/dev/loaders/src/glTF/2.0/pbrMaterialLoadingAdapter.ts).
- Blender writes the extension automatically when any emissiveFactor component > 1.0 (i.e. Emission Strength > 1 or bright emission color). **Documented** — [scene_gltf2.rst](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst).
- GlowLayer: `new BABYLON.GlowLayer("glow", scene)` makes all emissive parts glow using emissive color, emissive texture color and emissive texture level; default blur kernel 32; options `intensity`, `mainTextureRatio` (multiplies canvas size for the glow RT — "the smaller, the faster"), `mainTextureFixedSize` (consistent blur across devices), `blurKernelSize`, `mainTextureSamples` (MSAA, WebGL2 only); `addExcludedMesh`, `addIncludedOnlyMesh` (restrict the glow pass to e.g. the sole), `customEmissiveColorSelector`. No quantified cost is given. **Documented** — [glowLayer.md](https://raw.githubusercontent.com/BabylonJS/Documentation/master/content/features/featuresDeepDive/mesh/glowLayer.md) (public: https://doc.babylonjs.com/features/featuresDeepDive/mesh/glowLayer).

### Inferences
- Use `addIncludedOnlyMesh(soleMesh)` so the glow pre-pass renders only the sole, and set `mainTextureFixedSize` (e.g. 256–512) rather than a ratio so phone DPR does not blow up the blur target. **Inferred** from the documented options.
- Without a GlowLayer, emissive_strength > 1 only brightens the sole (clamped by the display/tonemapping); a bloom-like halo requires GlowLayer or the DefaultRenderingPipeline bloom (not researched). **Inferred**.

### Gaps
- No source quantifying GlowLayer or HighlightLayer frame cost on mobile; HighlightLayer page not fetched.

## KQ5. Texture compression and loading: KTX2/BasisU, WebP, Draco/meshopt decoders, how to produce them, mobile texture sizes and limits

### Takeaway
Babylon loads KTX2 (`KHR_texture_basisu`), Draco and meshopt out of the box but fetches the decoders from `cdn.babylonjs.com` by default — the docs say to self-host them in production via `KhronosTextureContainer2.URLConfig`, `DracoDecoder.DefaultConfiguration` and `MeshoptCompression.Configuration`. KTX2 files are produced with KTX-Software `toktx`, `gltf-transform uastc/etc1s`, `gltfpack -tc`, or Blender's gltfpack integration; UASTC for normal/ORM data, ETC1S for albedo.

### Cited Findings
- KTX2 concepts (Babylon docs): GPU-compressed textures stay compressed on the GPU, saving memory and cache misses; KTX2 stores a universal format transcoded (not expanded) to what the device supports; BasisU **ETC1S** = smaller, "performs worse on non-color data such as normal or metallic/roughness maps"; **UASTC** = higher quality, any texture type; Zstandard shrinks the file but not GPU memory; the decoder is an external package (<22 KB min) using Universal Texture Transcoders with MSC fallback; tools `toktx`, `ktxinfo`, `ktx2check`, `ktxsc`; `.basis` files work but KTX2 is preferred; Babylon picks ASTC/DXT/PVRTC etc. at runtime. **Documented** — [ktx2Compression.md](https://raw.githubusercontent.com/BabylonJS/Documentation/master/content/features/featuresDeepDive/materials/using/ktx2Compression.md) (public: https://doc.babylonjs.com/features/featuresDeepDive/materials/using/ktx2Compression).
- KTX2 decoder config (source): `KhronosTextureContainer2.URLConfig.jsDecoderModule` defaults to `https://cdn.babylonjs.com/babylon.ktx2Decoder.js`; `wasmUASTCToASTC`, `wasmUASTCToBC7`, `wasmUASTCToRGBA_UNORM/SRGB`, `wasmUASTCToR8_UNORM`, `wasmUASTCToRG8_UNORM`, `jsMSCTranscoder`, `wasmMSCTranscoder`, `wasmZSTDDecoder` default `null` (= default CDN); `DefaultNumWorkers` = min(floor(hardwareConcurrency × 0.5), 4), or 1; `DefaultDecoderOptions.useRGBAIfOnlyBC1BC3AvailableWhenUASTC = true` (speed over memory), `useRGBAIfASTCBC7NotAvailableWhenUASTC`, `forceRGBA`, `forceR8`, `forceRG8`, `bypassTranscoders`; engine caps `astc`, `bptc`, `s3tc`, `pvrtc`, `etc2`, `etc1` are passed to the decoder. **Documented** — [khronosTextureContainer2.ts](https://raw.githubusercontent.com/BabylonJS/Babylon.js/master/packages/dev/core/src/Misc/khronosTextureContainer2.ts).
- Forum excerpts on self-hosting: copy the CDN decoder files locally and point `URLConfig` at them; one user needed absolute URLs; the `@babylonjs/ktx2decoder` ESM package does not work via `URLConfig` because the URL is loaded with `LoadScript()` (UMD expected). **Documented (excerpts)** — [How to make ktx2Decoder on local](https://forum.babylonjs.com/t/how-to-make-ktx2decoder-on-local-request-it-takes-too-long/34760); [How to inject @babylonjs/ktx2decoder](https://forum.babylonjs.com/t/how-to-inject-babylonjs-ktx2decoder-into-babylon/62160/6).
- Draco: `DracoDecoder.DefaultConfiguration` → `https://cdn.babylonjs.com/draco_wasm_wrapper_gltf.js`, `draco_decoder_gltf.wasm`, fallback `draco_decoder_gltf.js`; override by assigning `DefaultConfiguration`; worker count 50% of logical processors capped at 4. **Documented** — [dracoDecoder.ts](https://raw.githubusercontent.com/BabylonJS/Babylon.js/master/packages/dev/core/src/Meshes/Compression/dracoDecoder.ts).
- Meshopt: `MeshoptCompression.Configuration.decoder.url` defaults to `https://cdn.babylonjs.com/meshopt_decoder.js`. **Documented** — [meshoptCompression.ts](https://raw.githubusercontent.com/BabylonJS/Babylon.js/master/packages/dev/core/src/Meshes/Compression/meshoptCompression.ts). glTF importer doc: decoders "are downloaded from the Babylon CDN" by default; "For production, the page recommends hosting them yourself"; meshopt "Decoder injection is not supported yet". **Documented** — [glTF.md](https://raw.githubusercontent.com/BabylonJS/Documentation/master/content/features/featuresDeepDive/importers/glTF.md).
- gltfpack: `-c`/`-cc`/`-cz` (EXT/KHR_meshopt_compression), `-tc` KTX2/BasisU (`-tu` UASTC; `-tp` for WebGL1 compat), `-tw` WebP, `-si R` simplification, `-kn`/`-km`/`-ke` keep names/materials/extras, `-mi` GPU instancing; KHR_mesh_quantization on by default (`-noq` off, `-vpf` float positions), `-vtf` disables texture-transform; KHR_materials_variants "fully supported", also clearcoat/sheen/transmission/iridescence/volume/specular preserved; vendor extensions discarded; Draco not supported; "Babylon.js supports compressed files in 5.0+ without extra setup". **Documented** — [gltfpack README](https://github.com/zeux/meshoptimizer/blob/master/gltf/README.md).
- gltf-transform CLI: `gltf-transform optimize in.glb out.glb --texture-compress webp`; `uastc in.glb out.glb --slots "{normalTexture,occlusionTexture,metallicRoughnessTexture}" --level 4 --rdo --rdo-lambda 4 --zstd 18`; `etc1s in.glb out.glb --quality 255`; `webp --slots "baseColor"`; `resize --width 1024 --height 1024`; `draco --method edgebreaker`; `meshopt --level medium`. **Documented** — [glTF-Transform CLI README](https://github.com/donmccurdy/glTF-Transform/blob/main/packages/cli/README.md) (full docs at https://gltf-transform.dev/cli, unreachable here).
- Blender: WebP export (no fallback unless "WebP fallback" chosen), Draco, meshopt (EXT or KHR), and gltfpack integration (`export_use_gltfpack`, `export_gltfpack_tc` = KTX2 texture compression, `export_gltfpack_tq`). **Documented** — [__init__.py](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/addons/io_scene_gltf2/__init__.py); [scene_gltf2.rst](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst).
- Texture-size practice (avatar vendors): Ready Player Me avatars default to 1024×1024 textures, can be limited down to 256×256 (`textureSizeLimit`), `lod` 1/2 cut triangles 25%/50%, `textureAtlas` merges to ≤2 draw calls, WebP "can reduce avatar file size by up to 40%". **Documented (search excerpt of official docs)** — [RPM 3D avatar API](https://docs.readyplayer.me/ready-player-me/avatar-api/3d-avatars); [RPM blog](https://landing.readyplayer.me/blog/improving-avatar-performance-with-new-avatar-api-options). Third-party Portals guide: RPM avatars "roughly 15k triangles, 1.5mb… 512x512 textures". **Documented (third-party)** — [Portals import specs](https://portals-help-center.super.site/portals-import-specs).
- MAX_TEXTURE_SIZE: webglfundamentals (2020) — 99% of devices support 4096, only ~50% > 4096; web3dsurvey Android (3D-texture limit, related): 4096 52%, 8192 43%, 16383 11%; Khronos list (2014): iOS GLES2 4096, GLES3 16384. **Documented (dated)** — [webglfundamentals cross-platform issues](https://webglfundamentals.org/webgl/lessons/webgl-cross-platform-issues.html); [web3dsurvey MAX_3D_TEXTURE_SIZE](https://web3dsurvey.com/webgl2/parameters/MAX_3D_TEXTURE_SIZE); [Khronos public_webgl thread](https://www.khronos.org/webgl/public-mailing-list/public_webgl/1410/msg00109.php). Babylon's `SceneOptimizer` presets cap render-texture size at 1024/512/256 for low/moderate/high degradation. **Documented** — [sceneOptimizer.md](https://raw.githubusercontent.com/BabylonJS/Documentation/master/content/features/featuresDeepDive/scene/sceneOptimizer.md).

### Inferences
- A sensible mobile set for this avatar: 1K albedo per major part (ETC1S) and 1K or 512 UASTC for normal/ORM; 2K only for a hero close-up tier; everything ≤4096 is safe on all phones, ≤2048 is comfortable. **Inferred** from the vendor practice and the 4096 ubiquity data.
- Babylon itself does not impose a texture-size cap beyond the GPU's `MAX_TEXTURE_SIZE`; no doc claims otherwise. **Inferred** (absence in docs).
- Draco and meshopt are mutually exclusive on the same geometry (gltfpack cannot read Draco); for a mobile avatar, meshopt + quantization is the lighter decoder path, Draco gives smaller files. **Inferred** from the gltfpack README.

### Gaps
- The public Babylon KTX2 page's device-format support table and the per-GPU target-format mapping were not retrievable (only the engine caps passed to the decoder are visible in source).
- No current (2024–2026) MAX_TEXTURE_SIZE survey for iOS was reachable.

## KQ6. Modular avatar at runtime: separate glTF parts on a shared skeleton, attach points, morph targets, and the KHR_materials_variants API

### Takeaway
Babylon's glTF loader builds bones linked to TransformNodes (`bone.linkTransformNode`), so animation must drive the nodes, not the bones; multiple skinned meshes can share one `Skeleton` via `mesh.skeleton`, rigid attachments use `attachToBone`, and `AssetContainer.instantiateModelsToScene` returns new skeletons/animation groups per instance. `KHR_materials_variants` is exposed as static helpers on the loader extension (`GetAvailableVariants`, `SelectVariant`, `Reset`, `GetLastSelectedVariant`) keyed on the glTF `__root__` node, with `defaultVariant`/`onLoaded` loader options.

### Cited Findings
- glTF skinning in Babylon: the loader "creates bones that are linked to the corresponding nodes in the scene"; "Changing bone transforms with linked nodes must be performed on the linked node" (direct bone edits are overwritten each frame); "the transform of the skinned mesh node MUST be ignored" per spec, so "the glTF loader loads the skinned mesh without its own transform and parents it as a sibling of the skeleton root node" and creates an extra node representing the glTF skinned-mesh node; one scene node can be referenced by multiple skeletons; pre-5.0 `overrideMesh` removed. **Documented** — [glTFSkinning.md](https://raw.githubusercontent.com/BabylonJS/Documentation/master/content/features/featuresDeepDive/importers/glTF/glTFSkinning.md) (public: https://doc.babylonjs.com/features/featuresDeepDive/importers/glTF/glTFSkinning).
- Skeleton sharing/cloning/attaching: several skinned meshes may reference the same skeleton (`mesh.skeleton = skeleton`, `mesh.numBoneInfluencers`); find them via `meshes.filter(m => m.skeleton === skeletons[0])`; `skeleton.clone("name")`; `sword.attachToBone(handBone, characterMesh)` (bone-relative transform, does not preserve previous world transform, inherits reference mesh scale); "Clothing that must deform should be skinned instead"; default 4 bone influences per vertex (3 on low-end), up to 8 in shader; bone matrices stored in a texture by default (`useTextureToStoreBoneMatrices = false` → uniforms, limits bone count); `computeBonesUsingShaders = false` for CPU skinning (incompatible with morph targets). **Documented** — [bonesSkeletons.md](https://raw.githubusercontent.com/BabylonJS/Documentation/master/content/features/featuresDeepDive/mesh/bonesSkeletons.md) (public: https://doc.babylonjs.com/features/featuresDeepDive/mesh/bonesSkeletons).
- AssetContainer: pools of entities not counted in the scene; `addAllToScene()`, `removeAllFromScene()`, `moveAllFromScene(keepAssets)`; `instantiateModelsToScene(nameFunction, cloneMaterials)` returns `{ rootNodes, skeletons, animationGroups }` and `entries.dispose()`; materials shared unless `cloneMaterials = true`. **Documented** — [assetContainers.md](https://raw.githubusercontent.com/BabylonJS/Documentation/master/content/features/featuresDeepDive/importers/assetContainers.md).
- Forum practice (search excerpts): every part mesh should be skinned to the **entire** skeleton ("even the head mesh needs the leg bones"); a user solved swaps by parenting armor to the character armature in Blender with automatic weights and disposing the extra skeleton after import; rigid items → parent to the bone with an offset / `attachToBone`; pitfall: removing all original meshes broke animation; a member suggested glTF variants as an alternative to mesh swapping. **Documented (excerpts)** — [Modular Characters - Swapping out armor…](https://forum.babylonjs.com/t/modular-characters-swapping-out-armor-clothing-and-body-parts/52595); [Composable body parts with skeleton and animations](https://forum.babylonjs.com/t/composable-body-parts-with-skeleton-and-animations/35530); [Same skeleton to multiple meshes](https://forum.babylonjs.com/t/am-i-able-to-apply-the-same-skeleton-to-multiple-different-meshes-body-parts-of-the-same-character/32893); [Advice on creating a Character Configurator](https://forum.babylonjs.com/t/advice-on-creating-a-character-configurator/52466).
- Animation retargeting: 9.0 announcement lists "animation retargeting"; changelog 9.7.0 fixes `AnimatorAvatar.retargetAnimationGroup`; 9.28.0 adds `RootMotionClip`/`RootMotionController`. **Documented** — [CHANGELOG.md](https://raw.githubusercontent.com/BabylonJS/Babylon.js/master/CHANGELOG.md); [9.0 forum post](https://forum.babylonjs.com/t/welcome-to-babylon-js-9-0/62940).
- KHR_materials_variants API (source): `KHR_materials_variants.GetAvailableVariants(rootNode): string[]`; `SelectVariant(rootNode, variantName: string | string[])`; `Reset(rootNode)`; `GetLastSelectedVariant(rootNode)`; data lives at `root._internalMetadata.gltf["KHR_materials_variants"] = { lastSelected, original: [{mesh, material}], variants: {name: [{mesh, material}]} }`; selecting sets `entry.mesh.material = entry.material`; loader options via `extensionOptions["KHR_materials_variants"]`: `defaultVariant`, `onLoaded(variants/selectedVariant)`; `onClonedObservable` keeps metadata valid on clone. **Documented** — [KHR_materials_variants.pure.ts](https://raw.githubusercontent.com/BabylonJS/Babylon.js/master/packages/dev/loaders/src/glTF/2.0/Extensions/KHR_materials_variants.pure.ts).
- Morph targets: Blender exports shape keys (optional normals/tangents, sparse accessors, shape-key animations). **Documented** — [scene_gltf2.rst](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/docs/blender_docs/scene_gltf2.rst). Babylon: CPU skinning is incompatible with morph targets. **Documented** — [bonesSkeletons.md](https://raw.githubusercontent.com/BabylonJS/Documentation/master/content/features/featuresDeepDive/mesh/bonesSkeletons.md).

### Inferences
- Pipeline that fits the docs: export the body with the full armature; export each limb/shirt/sneaker as a separate GLB skinned to the **same full armature** (same bone names/order); at runtime load parts into `AssetContainer`s, set `partMesh.skeleton = bodySkeleton`, and because glTF bones are node-linked, parent the part's mesh under the body's `__root__`/skeleton-root sibling position and dispose the part's own skeleton and duplicate TransformNode joints (or keep one skeleton and retarget via `AnimatorAvatar` where names differ). **Inferred** from glTFSkinning + bonesSkeletons + forum excerpts; needs testing.
- T-shirt/sneaker texture swaps are best done with KHR_materials_variants authored in Blender's Variants tab (ships materials in one file; swap = material pointer change, zero reload); mesh-shape swaps (limbs) need separate files. **Inferred**.
- The variants metadata is per loaded `__root__`, so each part GLB has its own variant set and `SelectVariant` must be called per root. **Inferred** from the metadata layout.

### Gaps
- No official Babylon doc page on composing multiple skinned glTF files onto one skeleton; practice is forum-derived and from excerpts only.
- `AnimatorAvatar` / retargeting docs were not fetched (path unknown; search budget exhausted).

## KQ8. Babylon.js vs Three.js differences that matter for this asset (brief)

### Takeaway
Both load transmission, volume, ior, dispersion, iridescence, specular, sheen, clearcoat, emissive_strength, basisu, webp, draco, meshopt and quantization; Babylon ships KHR_materials_variants and KHR_materials_diffuse_transmission built in, whereas Three.js's GLTFLoader has no diffuse_transmission and handles variants only through an external plugin.

### Cited Findings
- Three.js GLTFLoader `EXTENSIONS` (dev branch): KHR_binary_glTF, KHR_draco_mesh_compression, KHR_lights_punctual, KHR_materials_clearcoat, KHR_materials_diffuse_roughness, KHR_materials_dispersion, KHR_materials_ior, KHR_materials_sheen, KHR_materials_specular, KHR_materials_transmission, KHR_materials_iridescence, KHR_materials_anisotropy, KHR_materials_unlit, KHR_materials_volume, KHR_texture_basisu, KHR_texture_transform, KHR_mesh_quantization, KHR_materials_emissive_strength, EXT_materials_bump, EXT_texture_webp, EXT_texture_avif, EXT_meshopt_compression, KHR_meshopt_compression, EXT_mesh_gpu_instancing; **KHR_materials_variants is not built in** (supported via a separately registered plugin, three-gltf-extensions); **no KHR_materials_diffuse_transmission**; DRACOLoader/KTX2Loader/MeshoptDecoder must be set explicitly (`setDRACOLoader`, `setKTX2Loader`, `setMeshoptDecoder`) or required extensions throw. **Documented** — [GLTFLoader.js](https://raw.githubusercontent.com/mrdoob/three.js/dev/examples/jsm/loaders/GLTFLoader.js).
- Babylon 9.30.0: variants and diffuse_transmission built in (see KQ1); decoders auto-fetched from CDN unless reconfigured (see KQ5). **Documented** — sources in KQ1/KQ5.

### Inferences
- Moving from Three.js to Babylon removes the need for the variants plugin and gives a diffuse-transmission path, but introduces the TransmissionHelper's extra opaque pass as the default behavior for any transmissive material — the cost profile for the frosted shell changes and should be re-measured. **Inferred**.

### Gaps
- Three.js's own transmission render-target behaviour (`transmissionRenderTarget`, WebGL2 requirement) was not confirmed from the portion of the file read.

## KQ9. Blender → Babylon pipeline options: glTF vs legacy .babylon exporter, Sandbox validation, official guidance

### Takeaway
glTF via Blender's built-in exporter is the path Babylon documents for PBR content; the legacy `.babylon` Blender exporter docs still describe v6 for Blender 2.8 ("in beta") and are visibly stale; the Sandbox (sandbox.babylonjs.com) loads .glb/.gltf/.babylon/.obj/.stl/.ply/.splat with Inspector access and can generate `.env` IBL files.

### Cited Findings
- Babylon's Blender-to-glTF page: glTF add-on built into Blender since 2.8 and enabled by default; export .gltf/.glb; "the glTF exporter lets you export scenes using the PBR workflow"; axis conversion handled by exporter + loader (`__root__` rotated 180° Y, scaled −1 Z) — don't pre-correct; validate in Sandbox / Viewer / own loader page (serve over HTTP). **Documented** — [Blender_to_glTF.md](https://raw.githubusercontent.com/BabylonJS/Documentation/master/content/features/featuresDeepDive/Exporters/Blender_to_glTF.md).
- Legacy exporter page: v6 for Blender 2.8 "currently in beta", v5 for ≤2.79b in `deprecated`; apply scale before export; unpack images; one `.babylon` per animated object; test in Sandbox/Editor/Viewer. **Documented (stale content)** — [Blender.md](https://raw.githubusercontent.com/BabylonJS/Documentation/master/content/features/featuresDeepDive/Exporters/Blender.md). Blender_Tips page refers to `.babylon` export (smooth shading/edge split, limit bone influences to 4 via "limit total", rotation modes). **Documented** — [Blender_Tips.md](https://raw.githubusercontent.com/BabylonJS/Documentation/master/content/features/featuresDeepDive/Exporters/Blender_Tips.md). The BlenderExporter repository README could not be fetched (404 on `master` and `main`) — maintenance status **Unverified**.
- Sandbox: formats `.gltf .glb .obj .stl .babylon .bvh .ply .sog .splat .spz`; drag-and-drop incl. HDR environments; Inspector button; built-in environments; URL params `environment` (glTF only) and `toneMapping` (Standard/ACES/KHR_PBR_Neutral); installable PWA. **Documented** — [sandbox.md](https://raw.githubusercontent.com/BabylonJS/Documentation/master/content/toolsAndResources/sandbox.md). `.env` generation via Inspector Tools in the Sandbox. **Documented** — [HDREnvironment.md](https://raw.githubusercontent.com/BabylonJS/Documentation/master/content/features/featuresDeepDive/materials/using/HDREnvironment.md).
- Blender's exporter can also run gltfpack at export time (KTX2 + meshopt) — see KQ5. **Documented** — [__init__.py](https://raw.githubusercontent.com/KhronosGroup/glTF-Blender-IO/main/addons/io_scene_gltf2/__init__.py).

### Inferences
- Recommended flow: Blender 4.5 LTS/5.x → GLB (Principled BSDF only, variants via Variants tab, shape keys, full armature per part) → gltf-transform or gltfpack for KTX2/meshopt/resize → drop in Sandbox with the project's `.env` to check materials, variants, animation, and the Inspector statistics → load in app with self-hosted decoders. **Inferred** from the documented pieces.
